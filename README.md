# PromptScope

**安全な分析は、よい分解から。**

PromptScopeは、AIを使ったセキュリティ解析に入る前に、タスクの分解と
Agentへの指示品質を学ぶための教育用トレーナーです。検体・脆弱性・ログを
題材に、何を観測し、どのコンテキストを渡し、どこで判断を止めるかを
ローカルで練習できます。

## 現在の機能

- 起動時の導入画面から，専用例題のチュートリアルまたは演習を選択
- 8段階の吹き出しガイドで，タスク分解・指示とコンテキストの入力・採点・改善を体験
- 例題の回答例を入力でき，ガイドの前後移動・途中終了・再開始に対応
- マルウェア解析、脆弱性調査、ログ解析の3演習を切り替え
- 分割タスクの追加、削除、上下移動、選択
- タスクタイトル、Agentへの指示、渡すコンテキストの編集
- 演習ごとの15項目を、回答本文の引用に基づいて判定する5軸・100点満点の採点
- コードで集計する加点・減点・点数上限と、項目別の根拠・不足の表示
- 改善提案と強みの表示
- 80点以上・必須項目すべて充足・各軸12点以上を合格とする完了判定
- 通常演習はタイトルだけの骨組みから自分で指示・コンテキストを作成

## はじめて使うとき

起動時に「例題で使い方を学ぶ」を選ぶと，通常の3演習とは別の
「ファイル一覧から変更点を整理する」という例題が開きます．架空の入力データを読み，
吹き出しの「次へ」で進みながら，AI に渡す指示と前提の書き方を練習できます．
「回答例を入力」で具体的な書き方を確認し，「この計画を採点」で評価を体験してください．
例題は点数に関係なく終了できます．通常の演習の完了条件は80点以上・必須項目すべて充足・各軸12点以上です．

演習画面の「使い方・例題を見る」から，いつでも最初からやり直せます．
例題の編集内容や採点は演習の回答に影響せず，ガイドを終了すると編集中の演習に戻ります．
回答の保持は同じページを開いている間だけで，再読み込みすると初期状態に戻ります．

## 安全上の境界

PromptScopeは教育用プロトタイプです。画面上の演習では、検体を実行したり、
脆弱性を悪用したり、実環境へ変更を加えたりしません。採点時には入力した計画を
設定済みのLLMへ送信します。OpenRouter利用時は外部APIへ送信されるため、実在する
資格情報、個人情報、機密情報を入力しないでください。

採点は入力文を対象にしたLLM評価であり、実際のセキュリティ判定・脆弱性診断・
安全性の保証ではありません。評価結果を
現実の環境での実行許可やリスク受容の根拠に使わないでください。

## 起動と検証

Node.js `>=22.13.0` を用意してください。

```bash
npm install
```

### Ollamaを使う（ローカル既定）

Ollamaを起動し、使用するモデルを用意します。既定モデルは`qwen3.5:4b`です。

```bash
ollama pull qwen3.5:4b
cp .env.example .env.local
npm run dev
```

Windows PowerShellでは`cp`の代わりに次を使用できます。

```powershell
Copy-Item .env.example .env.local
```

モデルや接続先を変更する場合は`.env.local`の`OLLAMA_MODEL`と
`OLLAMA_BASE_URL`を編集してください。既定ではOllamaの自動判定に任せ、利用可能なら
GPUへオフロードします。CPU実行へ固定したい場合だけ`OLLAMA_NUM_GPU=0`を設定してください。
コンテキスト長とバッチサイズは`OLLAMA_NUM_CTX`、`OLLAMA_NUM_BATCH`で調整できます。
根拠付き採点には`OLLAMA_NUM_CTX=32768`以上が必要です。既存の`.env.local`で
4096などを指定している場合は更新してください。モデルと端末もこのコンテキスト長に対応する必要があります。
Ollamaでは要件の照合を慎重に行うため思考モードを有効にしています。モデルにより採点に数分かかる場合があります。

### OpenRouterを使う

`.env.local`を次のように設定します。`OPENROUTER_MODEL`には構造化出力に対応した
モデルIDを指定してください。APIキーはクライアントへ送信されません。

```dotenv
LLM_PROVIDER=openrouter
OPENROUTER_API_KEY=your-api-key
OPENROUTER_MODEL=provider/model-id
```

Cloudflareへデプロイする場合も、同じ名前の環境変数・シークレットをランタイムへ
設定してください。デプロイ環境から利用者のPC上のOllamaには接続できないため、
公開環境では通常OpenRouterを使用します。

### 検証

```bash
npm test
npm run lint
```

`npm run dev` でローカル開発サーバーを起動します。`npm test` はビルド、
サーバー描画、集計・根拠検証・API入力検証の回帰テストを実行します。
`npm run lint` は静的チェックを実行します。

### 採点の仕組み

採点基準は`app/lib/rubric.ts`で管理し、画面と評価プロンプトで共有します。
APIには`{ scenarioId, steps }`を送信し、演習の目的・環境・採点基準はサーバー側で取得します。
クライアントが送った演習説明や採点基準で上書きできません。

- 各軸に8点・8点・4点の3項目、合計15項目を設定。
- 未充足は0%、一部・抽象的は25%、具体的に充足は100%の加点。
- 本文をサーバーで参照番号付きの断片に分割。LLMは根拠・不足要素・理由を確認してから判定を返し、引用文の取り出しと点数・合否の計算はコードで実施。
- 不足要素が残ったままモデルが充足と判定しても、コードで部分的な充足へ引き下げる。
- 引用は回答の`instruction`または`context`に実在する必要があり、タイトルや設問だけでは加点しない。
- 各タスクの判断単位・入力・完了条件・成果物は、全タスクの引用が揃わない限り満点にしない。
- 必須項目の未充足は最大59点、部分的な充足は最大79点、空のタスクが混じる場合は最大49点。
- 課題と無関係・空の回答は0点、関連語だけの汎用的な計画は最大29点。
- 禁止操作は25点減点・最大29点、矛盾は15点減点・最大79点、未確認事項の断定は10点減点・最大79点、水増しは5点減点。
- 同じ禁止操作の二重減点を避け、未記載自体を追加の減点として扱わない。
- 最終得点は`max(0, min(点数上限, 加点合計 - 減点合計))`。
- 完了条件は80点以上・必須項目すべて充足・各軸12点以上。

判定の欠落・重複・不正な違反根拠・途中で切れた応答は採点エラーとし、高得点へ補完しません。
引用が実在しても意味の判定にはモデルの誤りが残るため、以下の実モデル検証で調整します。
入力は1〜20タスク、各本文欄4000文字以内、計画全体12000文字以内です。文・改行で分割した参照箇所は160個以内に制限し、短い文の大量入力で評価コンテキストが溢れることを防ぎます。
空の回答はモデル通信なしで0点を返します。

### 実モデルでの回帰検証

設定済みのOllamaまたはOpenRouterを使い、次を実行します。
OpenRouterでは通常のAPI利用料が発生します。通常の`npm test`では外部APIを呼びません。

```bash
npm run test:llm
# ケースを絞る場合
npm run test:llm -- unrelated generic good missing-stop missing-phase injection unsafe
```

`tests/fixtures/llm-cases.mjs`には、無関係な文章、抽象的な指示、単語の羅列、採点操作、
十分な計画、停止条件・主要工程の削除、タスク複製、禁止操作、旧初期案を収録しています。
各ケースの期待範囲・必須項目・違反判定を検証し、失敗時は非ゼロで終了します。
判定の詳細とモデル名は`outputs/evaluation-*/`へ保存します。
モデルやプロンプトを変更したら再実行してください。少数ケースの成功だけで精度を保証するものではありません。

## 主要ファイル

- `app/page.tsx` — 3ペインのワークスペース、タスク編集、採点・完了操作
- `app/globals.css` — アイボリー基調のレイアウト、レスポンシブ、フォーカス状態

- `app/lib/curriculum.ts` — 3演習の説明、環境、初期タスク
- `app/api/evaluate/route.ts` — LLM採点API
- `app/lib/rubric.ts` — 演習別の加点・減点・必須条件
- `app/lib/evaluator.ts` — 評価の型、JSON Schema、引用の検証、固定配点・上限・合否判定
- `app/components/evaluation-details.tsx` — 採点基準、引用、不足、減点・上限の表示
- `app/lib/llm/server.ts` — Ollama・OpenRouter接続と評価プロンプト
- `app/lib/tutorial.ts` — 演習から独立した例題，入力データ，回答例，ガイド文
- `app/components/tutorial.tsx` — 導入画面と，フォーカス・スクロールに対応した吹き出し

## 将来、コンテナ実行を追加する場合

実処理を扱う機能を追加する場合は、UIから直接実行できる設計にせず、少なくとも
次の境界を必須にします。

1. **隔離** — ホストや他の実行ジョブから分離した専用サンドボックスで動かす。
2. **使い捨て** — 実行ごとに新しい環境を作り、終了後に破棄する。永続状態を持たせない。
3. **通信遮断** — デフォルトでネットワークを無効化し、例外も明示的な許可制にする。
4. **最小権限** — 非特権ユーザー、読み取り中心、限定したCPU・メモリ・時間で実行する。
5. **監査** — 入力、イメージ、権限、操作、出力、終了理由を改ざん検知可能な監査ログへ残す。
6. **承認** — 実行前に対象・目的・範囲・リスクを確認し、人の明示承認と停止手段を要求する。

これらを満たせない場合は、実行機能を追加せず、現在のシミュレーションと
読み取り専用の教材に留めます。
