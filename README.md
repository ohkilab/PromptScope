# PromptScope

**安全な分析は、よい分解から。**

PromptScopeは、AIを使ったセキュリティ解析に入る前に、タスクの分解と
Agentへの指示品質を学ぶための教育用トレーナーです。検体・脆弱性・ログを
題材に、何を観測し、どのコンテキストを渡し、どこで判断を止めるかを
ローカルで練習できます。

## 現在の機能

- 起動時の導入画面から，専用例題のチュートリアルまたは演習を選択
- 8段階の吹き出しガイドで，タスク分解・指示とコンテキストの入力・採点・改善を体験
- 例題の回答例を入力でき，ガイドの前後移動・途中終了・再開始に対応
- マルウェア解析、脆弱性調査、ログ解析の3演習を切り替え
- 目的・問題文・環境・入力資料を指定した自作問題の作成、編集、削除
- 自作問題と回答をブラウザーに保存（最大20件）
- 問題の分野に応じた5軸の評価観点を編集し、LLMによる観点の提案を利用
- 公開インシデント事例や独自の参照資料を、問題別の評価プロンプトに反映
- 分割タスクの追加、削除、上下移動、選択
- タスクタイトル、Agentへの指示、渡すコンテキストの編集
- OllamaまたはOpenRouterを使った5軸・100点満点のLLM採点
- 分割粒度とコンテキスト充足のタスク別評価内訳
- 改善提案と強みの表示
- 総合80点以上かつ全タスクの最低基準を合格として「学習を完了」できる状態表示

## はじめて使うとき

起動時に「例題で使い方を学ぶ」を選ぶと，通常の3演習とは別の
「ファイル一覧から変更点を整理する」という例題が開きます．架空の入力データを読み，
吹き出しの「次へ」で進みながら，AI に渡す指示と前提の書き方を練習できます．
「回答例を入力」で具体的な書き方を確認し，「この計画を採点」で評価を体験してください．
例題は点数に関係なく終了できます．通常の演習は総合80点以上に加え，
各軸12点以上，全タスクの分割粒度とコンテキスト充足が各12点以上（20点換算），
中核項目に未充足がないことを満たすと完了できます．

演習画面の「使い方・例題を見る」から，いつでも最初からやり直せます．
例題の編集内容や採点は演習の回答に影響せず，ガイドを終了すると編集中の演習に戻ります．
標準演習と例題の回答は同じページを開いている間だけ保持され，再読み込みすると初期状態に戻ります．

## 自分の目的に合った問題を作る

演習一覧の「自分の問題を作る」から、タイトル、リスク、所要時間、分野、状況・問題文、学習目的、
環境・権限・制約を入力します。架空・匿名化したログや構成情報を入力資料として
添えることもできます。保存すると空の分析タスクから演習を始められます。
「問題・評価観点を編集」で問題文と評価設定を変更できます。問題を変更した場合は、
回答を維持して採点結果と完了状態をリセットします。
リスクと所要時間は自由に入力でき、演習の説明欄に表示されます。以前の保存データは
「計画演習」「自由」を初期値として読み込み、編集画面で変更できます。

分野を選ぶと、その分野の採点ルーブリックと5軸の標準的な評価観点が設定されます。
評価観点は各軸の「問題固有の観点」として採点され、自由に編集できます。
「目的と事例から評価観点を提案」で設定済みのLLMに具体化させることもできます。
分野が「その他」の場合は、工程の網羅を判定する「必要な工程」も1行に1つずつ指定・提案できます。
提案内容は保存前に確認・修正できます。問題を手入力して保存する際のLLM接続は不要です。
演習画面の評価観点・参照資料は折りたたみ内に表示し、改行、箇条書き（`-`、`*`、`+`、`・`）、
番号付きリスト（`1.`、`1)`）を反映します。HTMLなどの装飾は解釈せず、文字列として表示します。

参照事例には次の過去の公開報告を用意しています。画面上で出典、要約、評価に
追加する教訓を確認できます。教訓は報告をもとにした教材上の解釈で、出典の引用や
最新の対処手順ではありません。

- [SolarWinds Orion の侵害 / CISA AA20-352A](https://www.cisa.gov/news-events/cybersecurity-advisories/aa20-352a)
- [Log4Shell / CISA AA21-356A](https://www.cisa.gov/news-events/cybersecurity-advisories/aa21-356a)
- [Storm-0558 / Microsoft Security](https://www.microsoft.com/en-us/security/blog/2023/07/14/analysis-of-storm-0558-techniques-for-unauthorized-email-access/)

独自の公開資料はHTTPSの出典URLと要約・抜粋を最大3件登録できます。URLの本文は
自動取得せず、入力した要約を未検証の参考情報として扱います。事例と演習の
原因・被害を同一視せず、関係する観点だけを適用するよう評価プロンプトに指示します。
追加観点は5軸（各20点）の「問題固有の観点」の枠で採点し、ほかの項目の配点や安全上の基準を上書きしません。

## 採点の仕組み

採点ルーブリックは`app/lib/rubric.ts`に、分野（検体解析・脆弱性調査・ログ解析・
インシデント対応・その他）と例題ごとに定義しています。5軸は各20点で、軸の中の項目と
配点は分野ごとに異なります。

- 点数はすべて整数です。各項目は、充足で満点、おおむねで満点−1点、言及のみで満点の半分（切り捨て、最低1点）、
  未充足で0点です。平均や20点換算で出る端数は切り捨てます。
- 分割粒度とコンテキスト充足は、計画全体の項目（工程の網羅・分野の必須前提・問題固有の観点）と、
  タスクごとの項目に分かれます。タスクごとの項目は各タスクで判定し、平均を切り捨てます。
- 各タスクをどの工程に対応付けたかも判定し、どの工程にも当たらない・役割が重複するタスク1つにつき
  工程の網羅を1点下げます。タスクを増やすだけでは点が上がりません。
- コンテキスト充足の項目は、各タスクのコンテキスト欄の文だけを根拠にします。指示欄に書かれていても、
  コンテキスト欄になければ満たしたことにはなりません。
- 個人情報・秘密値を保護せずに記録・送信・共有させる指示は、禁止操作として扱い、情報保護にかかわる項目も満たしません。
- 誤字・無意味な文字列・存在しないタスクや資料の参照は、コンテキスト充足の「記述の正確さ」で扱います。
  無意味な文字列と識別子の食い違いはコードでも検出します。
- 共通の減点は、禁止操作を実行させる明示的な指示だけです（総合を最大29点に制限）。
- LLMへはタスクごとの判定と計画全体の判定を別々に並列で送ります。検証に失敗した呼び出しだけを
  1回再試行します。

自作問題の定義と回答はこのブラウザーのlocalStorageに保存されます。採点結果と
完了状態は保存せず、再読み込み後は再採点が必要です。別のブラウザーや端末との
同期はありません。ブラウザーの保存データを削除すると自作問題と回答も消えます。

## 安全上の境界

PromptScopeは教育用プロトタイプです。画面上の演習では、検体を実行したり、
脆弱性を悪用したり、実環境へ変更を加えたりしません。採点時には問題・資料・入力した計画を
設定済みのLLMへ送信します。OpenRouter利用時は外部APIへ送信されるため、実在する
資格情報、個人情報、機密情報を入力しないでください。
評価観点の提案時にも、問題文・資料・参照情報を同じLLMへ送信します。

採点は入力文を対象にしたLLM評価であり、実際のセキュリティ判定・脆弱性診断・
安全性の保証ではありません。評価結果を
現実の環境での実行許可やリスク受容の根拠に使わないでください。

## 起動と検証

Node.js `>=22.13.0` を用意してください。

```bash
npm install
```

### Ollamaを使う（ローカル既定）

既定モデルは`qwen3.5:4b`です．最初のターミナルでOllamaサーバーを起動し，
このターミナルは開いたままにします．

```bash
ollama serve
```

既にOllamaがサービスとして起動している場合，この操作は不要です．
`address already in use`と表示された場合も，通常は既存サーバーが
`127.0.0.1:11434`で動作しています．

別のターミナルでモデルを取得し，Ollamaへの接続を確認します．

```bash
ollama pull qwen3.5:4b
ollama ls
curl -fsS http://127.0.0.1:11434/api/tags
```

続けて同じターミナルでPromptScopeを起動します．

```bash
cp .env.example .env.local
npm run dev
```

ターミナルに表示されたローカルURLをブラウザーで開き，「この計画を採点」を実行してください．
Ollamaのターミナルに推論処理が表示されれば接続できています．

Windows PowerShellでは`cp`の代わりに次を使用できます。

```powershell
Copy-Item .env.example .env.local
```

モデルや接続先を変更する場合は`.env.local`の`OLLAMA_MODEL`と
`OLLAMA_BASE_URL`を編集してください。既定ではOllamaの自動判定に任せ、利用可能なら
GPUへオフロードします。CPU実行へ固定したい場合だけ`OLLAMA_NUM_GPU=0`を設定してください。
コンテキスト長（既定値`8192`）とバッチサイズは`OLLAMA_NUM_CTX`、`OLLAMA_NUM_BATCH`で調整できます。
採点時に同時に送る呼び出し数は`EVALUATION_CONCURRENCY`で変更できます（既定はOllamaで2、OpenRouterで4）。
Ollama側で並列に処理するには、Ollamaサーバーの`OLLAMA_NUM_PARALLEL`も確認してください。
並列数だけコンテキスト用のメモリを使うため、GPUのメモリに合わせて調整してください。
評価プロンプトとJSON Schemaを処理するため、`OLLAMA_NUM_CTX`は`8192`以上にし、
利用するモデルとPCのメモリに合わせて調整してください。
採点ではJSON Schemaで出力を制約するため、コンテキスト長にかかわらずOllamaの推論出力は無効にします．

GPUを確認する場合は，採点を1回実行した直後に次を実行します．

```bash
nvidia-smi
ollama ps
```

`ollama ps`で実行中モデルを確認でき，`nvidia-smi`でOllamaプロセスとGPUメモリ使用量を
確認できます．AMD GPUの場合は，導入済みのROCm監視ツールで確認してください．

接続エラーになる場合は，次の順番で確認します．

```bash
ollama -v
ollama ls
curl -fsS http://127.0.0.1:11434/api/tags
```

3つ目が失敗する場合はOllamaサーバーが起動していません．`ollama serve`を実行してから，
PromptScopeの開発サーバーを再起動してください．

### OpenRouterを使う

`.env.local`を次のように設定します。`OPENROUTER_MODEL`には構造化出力に対応した
モデルIDを指定してください。APIキーはクライアントへ送信されません。

```dotenv
LLM_PROVIDER=openrouter
OPENROUTER_API_KEY=your-api-key
OPENROUTER_MODEL=provider/model-id
```

Cloudflareへデプロイする場合も、同じ名前の環境変数・シークレットをランタイムへ
設定してください。デプロイ環境から利用者のPC上のOllamaには接続できないため、
公開環境では通常OpenRouterを使用します。

### 検証

```bash
npm test
npm run lint
```

`npm run dev` でローカル開発サーバーを起動します。`npm test` はビルドと
サーバー描画の検証、`npm run lint` は静的チェックを実行します。

実際に動いているサーバーを使う確認は、LLMのサーバー（SSHトンネルなど）を起動してから実行します。
`.env`・`.env.local`の設定を読み込みます。

- `npm run test:live` — LLMのサーバーへの接続、モデルの有無、`/api/generate`がJSON Schemaを守るかを確認します。
  `APP_BASE_URL=http://localhost:3000`を付けると、起動中のアプリのサーバー経由の採点も確認します。
- `npm run test:samples` — `tests/fixtures/score-samples.mjs`の分野別サンプル（目標20・50・80・100点）が
  目標点±8点に収まるかを確認します（10分ほどかかります）。モデル・評価プロンプト・ルーブリックを変えたときに使います。
- `npm run score:samples [サンプルIDの一部]` — サンプルを採点して目標点との差を表示します。
  `SAMPLE_VERBOSE=1`で項目ごとの失点も表示します。

## 将来、コンテナ実行を追加する場合

実処理を扱う機能を追加する場合は、UIから直接実行できる設計にせず、少なくとも
次の境界を必須にします。

1. **隔離** — ホストや他の実行ジョブから分離した専用サンドボックスで動かす。
2. **使い捨て** — 実行ごとに新しい環境を作り、終了後に破棄する。永続状態を持たせない。
3. **通信遮断** — デフォルトでネットワークを無効化し、例外も明示的な許可制にする。
4. **最小権限** — 非特権ユーザー、読み取り中心、限定したCPU・メモリ・時間で実行する。
5. **監査** — 入力、イメージ、権限、操作、出力、終了理由を改ざん検知可能な監査ログへ残す。
6. **承認** — 実行前に対象・目的・範囲・リスクを確認し、人の明示承認と停止手段を要求する。

これらを満たせない場合は、実行機能を追加せず、現在のシミュレーションと
読み取り専用の教材に留めます。
